# 追加の合成ケース8件 下書きのメモ

作成物: `cases.json`(8件)、`rubric-extra.json`(46項目 + 共通4項目)、`check.mjs`(手書き回答例による正規表現の検査)、`build.mjs`(上2つの生成元)。候補指示・過去の結果は読んでいない。題材はすべて架空。

## 各ケースの狙い
- e1-library-loan(適用条件): 2027年4月1日以降の新規登録は21日間、判定は登録日。答え(21日間)に加え、適用日と判定基準を残すか。旧規定14日間を答えにしない。expected=grounded。
- e2-book-price(片方の値なし): Aは240ページ・1800円、Bは300ページのみ。Bの価格がないため「1ページあたりの安さ」は判断できない、と書き、Bの価格を補わないか。expected=partial。
- e3-pool-temp(測定条件違い): 水温は朝27度/夕方29度で比較不可、入場料は両方400円で同じ。結論を先に書き、共通点を述べるか。expected=partial。
- e4-bike-metric(指標の意味): 1分あたり12円、基本料金は含まず金額も資料にない。15分=180円(時間分のみ)と、何を表し何を表さないか。expected=partial。
- e5-member-discount(複数の数値条件): 基本5% + 人数(3〜5人)5% + 期間(4〜6か月)3% = 13%。隣の区分(6人以上8%、7か月以上6%)を取り違えないか。expected=grounded。
- e6-club-pages(別ページ2主題): ページ1が活動日(土曜は月2回)、ページ2が部費(月額1500円、合宿は年に2回で別集金)。「月2回」「年2回」の取り違えを誘う。expected=grounded。
- e7-cafeteria-none(答えなし): 営業時間と定休日(日曜・祝日)は載るが、日替わりメニューは載らない。記載がないと言い、メニュー名を作らないか。expected=partial。
- e8-breakeven-explain(explain向け): 売上60万円・費用45万円のみ。損益分岐点の金額は出せない(固定費・変動費の内訳がない)。言葉の意味は補足として、資料の事実より後に置く。expected=partial。

## 迷った点
- e3・e4・e8の expectedStatus: 質問の一部は資料で答えられるため partial とした。production が grounded と判定する可能性がある(e3は特に)。実行前に、本番の判定に通して確かめるのが安全。
- e7: 資料に定休日の記載があるため、「定休日は営業しないのでメニューもない」という推論をする回答が出うる。これは断定の一種なので、`e7-no-speculation` に flag として入れ、人が確認する。
- e8: 資料に固定費・変動費がないので、金額が出せないことを期待値にした。出せるとする採点(例: 45万円や15万円の利益から作る値)は禁止項目に入れた。
- e4: 総額を問う質問に、基本料金の金額が資料にない。180円は「時間分のみ」として期待する。「合計180円」と言い切る回答は、`e4-excludes-base` と `e4-base-unknown` で落ちるが、専用の禁止項目はない(言い回しが多様で、正しい回答を誤検出しやすいため)。

## 採点の限界
- 自動判定は予備判定。`any` に入れていない言い回しは not_detected になるので、人が読んで確定する。
- `e2-cannot`・`e3-cannot` は「比較/判断/計算 + できません」という広い形。理由まで確認するものではなく、`e2-b-price-unknown`・`e3-conditions` と合わせて読む。
- `e6-no-invented-amount` は1500円以外のすべての金額を禁止する。「年間18000円」のような正しい計算も落ちるので、出たら人が確認する。
- `before` 項目は「then の語が出なければ順序違反なし」と仮定して検査した。実際の score.mjs の扱いと違う場合は、先に出る語の存在項目(e8-label など)と組み合わせて読む。`before.first` は `any` を持つ項目にした(e3-cannot、e7-no-info、e8-sales)。
- 空白除去後は、`x-no-summary` の改行基準の正規表現は効かない(固定6と同じ。この下書きでは変更していない)。
- 回答例は手書きで、実モデルの回答ではない。実モデルの回答で誤検出・見逃しが見つかったら、新しい版にして前の結果を残す(EXTRA_CASES.md の手順)。
