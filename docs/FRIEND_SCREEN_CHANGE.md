# フレンド画面の操作とプロフィール共有

## 受け入れ条件

- サイドバーのフレンド行を左にスワイプすると削除・ブロックを選べる。フルスワイプでは実行せず、確認でキャンセルできる。通信失敗はエラー表示し、削除成功時は会話をアーカイブする。
- 受信メッセージの写真は最新のFriendStoreから表示する。写真未設定・取得失敗は標準アイコンに戻り、次回更新で再試行する。
- 相手アイコンは44ptのタップ領域と読み上げラベルを持ち、タップで現在のプロフィールを開く。
- 「申請・招待」ボタンはフレンド申請とグループ招待の合計件数を表示する。同じ一覧で両方を承認・拒否でき、処理中は連打できない。空の種類は空状態を表示する。
- プロフィールに自己紹介を表示する。未設定は空状態とする。改行を保ち、Unicode scalar 500個までの完全な文字を共有する。

## 保存・互換性・安全性

自己紹介は既存の認証済みPOST /api/chat/meにoptional bioを追加して本人のユーザーレコードへ保存する。文字列以外・500 Unicode scalar超は400。未指定は維持、空文字は消去。既存GET /api/chat/friendsのフレンド限定レスポンスにoptional bioを追加する。第三者検索の公開範囲は拡張しない。プロフィール画面とプライバシーポリシーに共有範囲を表示する。

既存保存データと旧サーバーレスポンスはbio欠落を許容する。新アプリのbioは旧サーバーでは無視される。サーバーを先行更新すれば、新アプリで共有が有効になる。スキーマ移行・設定変更は不要。ロールバックは前版へ戻せる追加型変更で、友達関係・会話・保存済み自己紹介を破壊しない。

フレンドの写真ダウンロードは取得前後に更新世代・リクエスト順を確認し、現在の対象レコードの写真だけを更新する。取得中の削除や、別更新で取得した新しい写真を巻き戻さない。

既存のKVユーザーレコード更新は外部I/Oを含み、Durable Object経由だけで完全な排他が保証される設計ではない。今回の変更は既存保存経路に合わせる。サーバー全体の排他設計の変更は別課題。
