# 出典選択と検索の障害分離（2026-10-09）

作業先 `.worktrees/rag-wip`、`codex/rag-wip`。ユーザーの進行指示に基づき、前回の100ページstaging検証で残った余分な出典と検索の不安定さに対応した。Highの設計・独立Planner・脅威／障害分析・独立コード／安全レビューを実施した。今回のコードはまだstagingへ配信していない。本番、migration、binding、flag、iOS、秘密情報の恒久設定を変更していない。

## 原因と変更

- 単純質問でもRRF優先の順位融合から複数ページを残すため、光合成の根拠と植物の根のページが同時に出典となった。短い単一の定義／意味／仕組み質問だけを明示的に対象とし、有効な全件reranker結果に一意の最上位がある場合、そのページを選ぶ。固定score閾値は追加しない。同点・不正応答・障害時は従来のRRF選択を使う。
- 比較・詳細値・一覧・要約・複合質問は従来の最大5ページを維持する。同ページのparent／neighborの追加と構造化citationも維持する。
- Vectorize／Embeddingの障害が、成功したD1 FTSの検索結果も消していた。意味検索とFTSを独立して待ち、各branchを4秒で打ち切る。Vectorize候補のD1照合も2秒で打ち切り、成功したFTSを維持する。FTSだけが失敗した場合も、D1で所有者・scopeを再確認できたvector候補を使う。両方失敗／根拠不足は通常チャットへfallbackする。
- 検索反映の確認は全ID・metadata検証に加え、先頭／中央／末尾の異なるページを最大3件queryする。accountKey／sourceId／folderId／pageNumberで限定し、そのページの現chunk IDが返ることを確認する。前後のD1 snapshot再確認を維持する。100ページ試験のprobeは1／51／100ページ。AI推論は追加しない。

## 検証

- 修正前のコピーで選別した7回帰ケースを実行し、6件失敗を確認。余分な出典、片側障害で証拠消失、代表ページ未反映でもreadyになる状態を再現した。元の作業ツリーを戻す操作は行っていない。
- 最終対象テスト63件成功。新規回帰27件と関連既存テストを含む。停止したVectorize／D1照合、同点・不正reranker、複合質問の複数ページ保持、100ページ反映、ユーザー／scope分離を検証した。
- Worker全テスト827件成功、失敗・skip 0。既存の「Vectorize障害なら全fallback」テストは、意図した新契約に合わせ、FTS出典を維持することと両branch障害のfallbackを確認する形へ更新した。
- 実Workers AI rerankerを合成ページ86／1／87の3候補で1回実行。799ms、最上位は光合成の1ページ。scoreは1ページ0.018376、87ページ0.0000396、86ページ0.0000374。従来の融合選択は3ページを残すが、新しい単純質問の選択は1ページとなった。本文・秘密情報を報告へ含めない。モデル単体＋選択処理の確認であり、公開Worker／100ページ全体のE2E再検証ではない。

## 安全性・互換性・運用

accountKeyの生成、Vectorizeの所有者filter、D1の所有者／scope／削除状態、neighborの再照合を維持する。モデルのidやmetadataから権限を推測しない。retrieved textのUNTRUSTED JSON扱い、引用IDのWorker生成、通常チャット、RAG無効時の経路は維持する。遅延したbindingの読み取りは取り消せないため、timeout後の結果を採用しない。本文ログは追加しない。

検索費用は、失敗時にも成功したbranchを利用することでrerankerを呼ぶケースが増える。反映確認は最大50回のID取得＋3回のqueryとなる。契約プランのsubrequest上限、1,000chunk規模とiOSの20秒timeoutは別途検証する。今回の外部AI送信は合成3候補の1推論のみであり、総請求額は確認していない。ユーザーの実紙資料は外部送信していない。一時ローカル資格情報を削除し、私有検証プロセスも終了した。

新しいAPI応答形式、migration、Embedding形式変更はない。再Embeddingは不要。ロールバックは今回のreference選択、branch障害分離、page probeを戻し、既存schemaと削除処理を維持する。配信時は対象テスト済みスナップショットを使い、既存のRAG／AI承認flagをfalseに保つ。

## 残る限界

単一ページ選択は回答の十分性を保証しない。単純に見える質問でも複数ページに根拠が分散する場合があるため、独立した資料・言い換え質問で欠落を評価する。現在の制約は複合要求を保守的に複数選択へ残すが、日本語全般の意味解析ではない。

代表3ページのprobeは全ページやlibrary検索の可視性を保証しない。前回の実環境の一時fallback原因は未確定であり、今回の障害分離をその原因確定として扱わない。staging配信後、同じ質問を登録直後から繰り返し、成功率と候補の変化を測る必要がある。100ページの実環境再検証、厚い資料、実紙OCR、実iPadは未実施。

Projectの資料の更新が必要: [設計] `HYBRID_RAG.md`の複製。Desktopの複製やProjectへのアップロードは変更していない。
