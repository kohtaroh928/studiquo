# 日本語検索・OCR・100ページPDFの品質評価（2026-10-08）

現状は本番有効化を推奨しません。合成教材では基本的な検索が機能しましたが、Rerankingによる正解ページの脱落、曖昧質問の判定範囲、比較質問の必要ページ不足、答えがない質問への参照混入を確認しました。

## 評価範囲

リポジトリに実教材PDFがなく、実資料の指定もなかったため、20テーマ・各5ページの合成日本語教材を作成しました。100ページのうち80ページは文字レイヤーあり、20ページは画像のみの印刷文字です。PDFKitでpage.stringを抽出し、画像ページはアプリと同じVision設定（accurate、ja-JP/en-US、language correction）でOCRしました。先頭・中間・末尾の描画を目視確認しました。

これは短い説明・見出し・段落が中心の100ページPDFです。自然な教材の図表、二段組、手書き、汚れ、傾き、数式、長いページを網羅しておらず、「実資料を代表した評価の完了」ではありません。OCRはmacOS Visionによるもので、実iPadとの差も未確認です。

検索は実装のindexSource/retrieve/chunkPage/queryPlan/RRFと0006 migrationをそのまま使用。Workers AIのEmbedding・Rerankingは実Cloudflare REST APIです。D1部分は実SQLite FTS5、Vectorize部分はaccountKey付きローカルの厳密cosine検索で代替しています。実Vectorizeの近似検索・反映遅延やstaging Workerのbinding経由性能はこの結果に含みません。production/stagingの保存データや設定は変更していません。

## PDF・OCR

- 100ページを5ページ×20 batchで索引化し、100 chunkを生成。出典のページ番号を保持。
- 同じsourceHashで全100ページを再送してもEmbedding呼出しは増えませんでした。
- 文字レイヤー80ページ: 正規化後の文字誤り率0%、重要文の完全一致80/80。
- OCR20ページ: 画像のみであることを確認。文字誤り率 **0.160%**（7508文字中12編集、NFKC・空白・ページ末尾番号を正規化）。
- OCRの重要文完全一致 **18/20**。不一致はpage60とpage75。OCR時間中央値 **204 ms/ページ**。
- PDFKitでは文字とレイアウトを確認。環境のPopplerにはAdobe-Japan1のlanguage packがなく、文字レイヤー描画の検証はPDFKitへ切り替えました。

## 検索結果

正解ページは実行前にfixtureへ固定。60問は言い換え20、OCRページ20、比較10、曖昧5、資料外5。追加で既存判定が認識する曖昧表現5問と明示質問5問を比較しました。

Recall@5は「正解ページのうちTop5 chunkに含まれた割合」の質問ごとの平均。MRR@5は最初の正解ページの逆順位の平均です。chunk単位の実出力を使用し、同じページが複数回ある場合も順位を圧縮していません。

| 質問群 | 処理 | Recall@5 | MRR@5 |
| --- | --- | --- | --- |
| 日本語の言い換え（20問） | BM25 | 100.0% | 0.845 |
| 日本語の言い換え（20問） | Vector | 95.0% | 0.863 |
| 日本語の言い換え（20問） | RRF | 100.0% | 0.860 |
| 日本語の言い換え（20問） | Rerank後 | 85.0% | 0.627 |
| OCRページ（20問） | BM25 | 100.0% | 0.877 |
| OCRページ（20問） | Vector | 100.0% | 0.925 |
| OCRページ（20問） | RRF | 100.0% | 0.925 |
| OCRページ（20問） | Rerank後 | 90.0% | 0.900 |

- 日本語の言い換え: Rerank前20/20 → 後17/20。正解脱落はdef-6（音）、def-7（光の屈折）、def-15（確率）。
- OCRページ: Rerank前20/20 → 後18/20。正解脱落はocr-8（月の満ち欠け、page40）、ocr-14（三角形、page70）。OCR本文の重要文はこの2ページでは完全一致しており、OCR誤字だけが原因ではありません。
- 比較10問: 何らかの正解ページは10/10。必要な両ページがTop5に入ったのは **5/10**。ページごとのRecall@5は75%。Multi Queryの判定は10/10で動作。
- 自然な曖昧質問「これのしくみを説明して」: 正解ページは **1/5**。queryPlanのambiguous判定は **0/5**。
- 既存判定が認識する「これを説明して」: ambiguous判定は5/5。RRF Top5に正解ページ5/5、Rerank後は **2/5**。同じ履歴の明示質問を送る対照は4/5。retrieval.jsはEmbedding/FTSではrewriteを使いますが、rerankerには元の曖昧なqueryを渡すため、履歴の主題が最終順位へ反映されにくい点を確認しました。
- 主評価の正解あり55問: Recall@5 **79.1%**、必要な正解ページがすべてそろった質問 **41/55**。
- 構造化出典のpageNumberとchunkの保存ページ一致: **350/350（100%）**。これは番号整合性であり、出典の質問への関連性100%を意味しません。
- 資料に答えがない5問: **5/5で5件の参照が返りました**。意味検索に最小関連度の判定がなく、ヒット0件の通常chat fallbackには入りません。Geminiの回答は生成しておらず、幻覚の有無は未評価です。
- 主評価retrieveの時間中央値863.5 ms、最大1782 ms。ローカルDB/cosineと実AI APIを組み合わせた時間です。

## 改善・残作業

1. 日本語の自然な指示語質問をRewrite判定に追加し、rewriteした質問をRerankingでも使用する案を検証する。
2. 指定モデルbge-reranker-baseで日本語の順位が悪化した例を回帰fixtureにし、RRFとの組み合わせ・fallback条件を評価する。モデル変更はユーザー指定があるため別途検討する。
3. 比較・複合質問で必要な各主題のページをTop5に残す方法を評価する。
4. 答えがない質問に対する関連性判定と、Geminiの資料不足時の応答を評価する。単純な固定score閾値の採用前に、関連・非関連データで校正する。
5. 許可された実教材で、図表・数式・手書き・二段組・低品質scan・長文を含む100ページPDFを評価する。
6. 実Vectorize/D1 bindingと実iPadで同じgolden質問を再実行する。

今回、検索の本体コードは変更していません。品質の悪化を隠すためにgoldenページや期待値を変更していません。`RAG_ENABLED=false`を維持します。
