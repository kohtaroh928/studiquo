# RAGのセキュリティ強化の記録（2026-10-20）

OWASP LLM Top 10（2025）で洗い出した弱点への対応を、ブランチ`claude/rag-contract`にまとめた記録。仕様の正は[RAG_PROMPT_CONTRACT.md](RAG_PROMPT_CONTRACT.md)。本番へのデプロイ・push・mergeはしていない（RAGのフラグはfalseのまま）。

| 弱点 | 対応 | 状態 |
| --- | --- | --- |
| 実モデルが資料内の命令に従うか未測定 | 実API評価48呼び出し。従った例は0/44（[報告](RAG_INJECTION_LIVE_REPORT.md)） | 測定済み（標本は小さい） |
| 抜粋が`instructions`内 | 別の入力項目へ移す切替`RAG_CONTEXT_AS_INPUT`。両配置で差が出ず、凍結ゴールデン10件を書き換える必要があるため既定は現行 | 切替は実装・評価済み、既定は変更せず |
| 通常チャット（共有ノート）のリンク | `noteContext`付きでもサーバーがリンクを除く | 対応済み |
| 取り込み時の検査が見えない文字だけ | 命令らしい語句を数えてログ（`injectionHints`）。本文は変えない | 対応（検出のみ） |
| 構造化入力は取り込み時に除かない | 検索時に必ず除く。保存済みの行でも除くテスト | 対応済み |
| 出力フィルタがリンクだけ | 内部ID（64桁hex、`sourceId=`/`chunk_id:`）も除く。teenの回答は完成後にモデレーション | 対応済み |
| アプリのリンク無効化が未確認 | 判定を`openableURL`に集約しXCTest。http/https以外は常に開かない | 単体テスト済み、**目視確認は未実施** |
| PII・秘密が送られる | `redact-pii.js`で送信前に伏せ字（メール・電話・Luhnカード・マイナンバー表記付き・鍵） | 対応済み |
| 共有Vectorize索引 | 別アカウントのaccountKeyを報告した一致をD1の前に捨てる（3段目）。外すと失敗するテスト | 対応済み |
| 共有資料のACL未設計 | 解禁条件と受け入れ試験を文書化（[設計](RAG_SHARED_SOURCES_DESIGN.md)）。索引種別がpdf/notebookだけであることをテストで固定 | 設計のみ（未提供の機能） |
| 生成後の根拠検証なし | 規則による数え上げを影モードで実装（`rag_grounding`ログ）。実API6呼び出しで確認 | 段階A・B対応、C未実施 |
| 閾値が未較正 | 独立した評価セットがないため未実施（[メモ](RAG_GROUNDING_VERIFICATION_PLAN.md)§6） | **未対応** |
| RAG内部のAI呼び出しが計上されない | 呼び出し数を上限（埋め込み3・リランク1）で固定しテスト、`aiCalls`をログへ。クレジットは1チャット定額のまま | 対応（計上方式は変更せず） |
| `npm audit` 4件 | lockの更新（本番・開発とも0件、隔離コピーでサーバーテスト成功）は、MCP SDKの更新を含みWorkerに届くため**別ブランチ`claude/deps-audit-fix`に分離**。stagingでMCPを確認してから入れる | 分離済み（未適用） |
| Workers AIモデルが版固定できない | IDを`MODELS`に固定しテストで凍結。提供元の無告知変更は防げない | 緩和のみ |
| Doclingの実環境隔離が未検証 | Docker/Linux環境がなく検証できない | **未対応** |
| 友人の候補指示の検査に見逃し | 検査を広げる（リンク・出典ID・プロンプト開示・一般知識・偽ロール・隠し文字・全角/空白） | 緩和（見逃しはあり得る） |
| ブランチ未統合 | 統合・push・デプロイは依頼がないため実施せず | **未実施** |

## 独立レビュー（2026-10-20）と対応

`code-reviewer`と`security-reviewer`の2エージェントが、13コミットを別々にレビューした（実APIは使わず、読み取り専用）。指摘と対応:

| 指摘 | 対応 |
| --- | --- |
| 高: `RAG_CONTEXT_AS_INPUT`の再試行で、失効した資料が`input`に残って再送される | 文字列を返す分岐でも`input`を元に戻す。直すと通り、外すと失敗するテスト |
| 中: リンク除去の要否が送信後の再検証で外れる（アプリは`ragStatus`が非nullなので開かない） | 送信時に「抜粋を送ったか」を確定して使う。回答中に資料が消えるテスト |
| 中: `sourceId: 値`（空白あり）が断片で漏れる | 名前・区切り・値が別断片でも保留する。断片1〜200文字のテスト |
| 中: `03-14-2023`などを電話番号として伏せる | 桁数（10〜11）で絞る |
| 中: 全角の電話・メール・カード・マイナンバー、`Bearer`・`AIza`・`api_key=`等が伏せられない | NFKC正規化の見え方で検出して元の文字へ対応づける。鍵の形を追加 |
| 中: teenの出力モデレーションがRAG外のチャットにも掛かる／タイムアウトなし | 外から入った文字（抜粋・添付ノート）を含む回答に限る。4秒で打ち切り |
| 低: 異体字セレクタ・空白フィラー・ZWJ連続が残る | 除去に追加。ZWJ/ZWNJは2個以上の連続を除く |
| 低: 引用タイトルが無害化されない | モデルに見せるタイトルだけ同じ除去と伏せ字を通す |
| 低: `javascript:`/`mailto:`等のMarkdownリンク、画像が残る／URL直後の日本語が削られる／サロゲートペアの途中で切れる | スキーム付き全リンクと画像を除く。URLは英数字の範囲で終える。強制切り出しでペアを割らない |
| 低: 友人の候補指示の検査が多くの言い換えを通す／否定の誤判定 | 無効化の言い換えを否定で救えない規則に移し、否定は同じ文の中だけで判定。レビュー指摘の文例をテストに追加 |
| 低: 実API評価の`preview`が二重 | スクリプトを直した。保存済みの結果JSONは二重のまま（部分一致の判定には影響なし） |
| 低: lockの更新はWorkerの実行時依存（MCP SDK 1.30→1.32）に及ぶ | 別ブランチ`claude/deps-audit-fix`へ分離し、stagingで確認してから入れる |
| 低: teenの判定はクライアント申告のヘッダー依存 | 契約文書に制約として明記 |

レビューが問題なしとしたもの: 通常文の欠落・並べ替えなし、ReDoSなし、エラー経路の返金・push条件は不変、越境の3段（フィルタ→一致のaccountKey→D1）、ログに本文なし、鍵は成果物に出ない、「既定の文面は変えていない」は成り立つ。

## 実API評価で見つかった別件（セキュリティではない）

- 表形式の資料（`| 電流計 | 5000円 … |`）に対して、価格の質問が「確認できない」になる。
- 価格が抜粋にあっても、「3個買うと合計は」のような計算を含む質問が「確認できない」になる。
- どちらも検索側の「答えられるか」の判定が先に止めている。取りこぼしの改善は別の課題。

## 再現

- 実API: `mcp-server/scripts/rag-quality/injection-live.mjs`、`grounding-live.mjs`（`STUDIQUO_RAG_OPENAI_KEY_FILE`でキーの場所を渡す。1回の実行は最大24／6呼び出し）。
