# パスワード変更直後、別拠点で旧パスワードが通る問題(L-6)の設計

状態: 設計(2026-11-09)。リスク分類: High(認証)。

## 問題

パスワードのハッシュは KV(`account:local:<email>`)にある。KV は書き込みが他の拠点へ伝わるまで最大約1分かかり、その間、別拠点は変更前の記録を返す。変更前のパスワードで、その1分間はサインインできる。パスワード漏えいに気づいて変えた直後が、いちばん狙われやすい。

## 方針

すでにアカウントごとに強整合の Durable Object(`RATE_COUNTER` の `account-gen:<emailHash>`、`rate-counter.ts`)があり、パスワードを設定するたびに世代 `gen` を進めて、記録にも `gen` を入れている。これを使う。

- パスワードの記録は、DO の `commitAccountRecord(key, json, gen)` が書く。DO の中で「`gen` が、すでに書かれた記録の世代より小さければ拒否。そうでなければ KV へ書き、その世代を `committedGen` に残す」を1つの手順で行う(`blockConcurrencyWhile`)。同じメールで2つの設定が同時に走り、遅いハッシュの古い世代が後から着いても、新しい記録を上書きしない(拒否された側は 503 で再試行できる)。独立レビューで指摘された締め出しの競合への対策。
- `verifyLocalAccount` は、ハッシュを比べたあと、`record.gen < committedGen` なら古い記録として拒否する。一致・不一致にかかわらず DO へ問い合わせるので、古い記録の拒否は間違ったパスワードと応答時間が変わらない。記録が無いメールにも同じ問い合わせをして、アカウントの有無が時間で分からないようにする。
- DO への問い合わせは独自の try/catch の中で行い、失敗したら通す(fail-open)。外側の catch に入れると、障害時に全員拒否になる。
- 古い記録を拒否したときは、旧PBKDF2記録の Argon2id への移行(upgrade)もしない。

## 互換と安全

- `committedGen` がまだ無いアカウント(配備前に作られた)は、検査しない(従来どおり)。次のパスワード設定から有効になる。段階的で、migration は要らない。
- `gen` の無い旧記録は 0 として扱う。
- DO の呼び出しが失敗したときは、サインインを通す(従来と同じ約1分の窓に戻るだけ)。DO の障害でサインイン全体を止めない。失敗はログに残す(個人情報なし)。
- DO への問い合わせは、記録のある全てのサインイン試行に1回増える(レート制限は既存のまま)。
- `upgradeAccountIfCurrent`(旧PBKDF2→Argon2idの移行)は `gen` を変えないので影響しない。
- アプリ・API の形は変わらない。旧アプリとの互換問題なし。ロールバックは、Worker を前の版に戻すだけ(DO に残る `committedGen` は、前の版が読まないので無害)。

## 悪用・障害の検討

- 古い記録を持つ拠点でも、新しいパスワードは古い記録のハッシュと合わないので、その拠点では伝播するまで新パスワードも通らない(現状と同じ。変更した拠点では即座に通る)。
- 世代を戻す入力は無い(`commit` は単調増加、DO は外部から呼べない)。
- アカウント削除: `retireAccountGeneration` は `committedGen` を変えない(削除済みの記録の扱いは別の仕組み)。

## 受け入れ条件

1. パスワード変更(設定)後、変更前の記録(`gen` が小さい)が読まれる状況で、旧パスワードは `false`。
2. 同じ状況でも、現在の記録 `gen == committedGen` のパスワードは `true`。
3. `committedGen` が無いアカウントは、従来どおり通る。
4. `nextAccountGeneration` の後に書き込みが完了しなくても、旧記録でのサインインは通る(確定は書き込みと同時)。
8. 同じメールの2つの設定が逆順に完了しても、新しい世代の記録が残り、古い方は失敗(再試行可)になる。
5. DO が失敗したときは通る(fail-open)。
6. 旧PBKDF2記録の移行が、従来どおり動く。
7. 拒否の経路が、間違ったパスワードと同じ種類・同じ量のハッシュ計算をする。

## 未対応(スコープ外)

- `app.ts` のパスワード再設定の `replacedPassword` 判定(`account:local` の存在確認)も KV の古い読み取りを使う。変更直後の別拠点でリセットすると、変更済みと判定されないことがある。L-6 とは別の既存の穴。
- アカウント削除の `retireAccountGeneration` は `committedGen` を変えない。
- パスワード変更後に旧セッションが約1分生きる点(セッション切り捨ての KV 伝播)は別問題。
