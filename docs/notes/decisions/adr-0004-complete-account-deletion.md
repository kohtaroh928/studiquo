# ADR-0004 アカウント削除で、学習スナップショットと共同編集ノートも消す

## 背景

プライバシーポリシーは、アカウントを削除すると端末とクラウド上の学習資料などを削除すると書いている。独立レビュー(2026-10-09、main `50c34d9`)で、次の2種類が削除後も残ると指摘され、コードで確認した。

1. **学習スナップショット(`snapshot:<トークンのハッシュ>`、`actions:<トークンのハッシュ>`)**: 期限なしで保存していた。削除は、現存するセッション行から所有トークンを割り出して消す。セッション行は90日で消えるので、古いトークンのスナップショットは持ち主を辿れず、残り続ける。
2. **共同編集ノート(`DOCUMENT_ROOM`)**: 削除の処理が一度も参照していなかった。さらに、部屋の参加者を**セッションのトークンのハッシュ**で記録していたため、サインインし直すと持ち主が自分の部屋に入れず、招待された人(アカウント固有のチャットのキーで登録)は一致せず入れなかった。

## 決定

- **スナップショットと保留中の操作**: トークンのハッシュで保存するものには、そのトークンのセッションの残り日数を有効期限として付ける(`remainingValiditySeconds`)。セッションと一緒に消えるので、削除が辿れない取り残しは生じない。アカウント単位のコピー(`snapshot:<アカウントのハッシュ>`)は期限なしで、削除時に消す(従来どおり)。
- **共同編集ノートの参加者**: セッションごとのキーをやめ、チャットと同じ、アカウントごとに変わらないキー(`resolveChatUserKey`)で記録する。招待(友達コードから引くキー)と同じ名前空間になる。
- **削除時の探し方**: 部屋の作成と招待のとき、`doc-room:<参加者のキー>:<部屋ID>` に役割を書く。削除は、このキーの一覧から部屋を探す。
  - 一覧は「どこを見るか」を示すだけで、**何をするかは部屋自身が決める**(`removeAccount`)。一覧が古い、または部屋が一度消えて別の人が同じIDで作り直した場合でも、持ち主でない人の削除が他人の部屋を消すことはない。
  - 持ち主の部屋は丸ごと消す(本文、提案、参加者)。先に、他の参加者の一覧のキーを消してから部屋を消す。部屋が消えたあとでは、それらのキーを誰も辿れないため。
  - 招待されただけの部屋では、その人の席と、その人の未決・却下の提案を消す。承認済みの提案は、持ち主の文書の一部として残るが、書いた人のキーと、置き換えた元の文は消す。最後の1人が抜けた部屋は消す。
  - 作成のときに一覧の書き込みが失敗しても、クライアントの再送(`already_initialized`)で、部屋が自分のものなら一覧を書く。
  - 部屋の削除は、削除の最後のデータ処理にする。1つの部屋が失敗しても他の部屋は進める。1回の実行で扱う部屋は40まで。残りは再試行で終える(同意なしの招待で一覧を水増しされても、削除のほかの処理を止めない)。

## 採らなかった案

- 全件を走査して持ち主を探す案: 退会の処理量がユーザー数に比例する(既知のM-7)のを悪化させる。
- ポリシーの文面を弱める案(方針2): 利用者の期待に反するので採らない。

## 互換性

- アプリ側の変更は不要。リクエストの形は変わらない。
- **この変更より前に作られた部屋**: 持ち主が、サインインごとに変わるトークンのハッシュで記録されている。デプロイの直後から、持ち主はその部屋に入れなくなる(トークンは最大90日有効なので、サインインし直していない持ち主も含む。ただし、そのトークンのチャットユーザーが既にあるアカウントは、キーがトークンのハッシュのまま続くので例外)。逆に、旧部屋の被招待者は、もともとチャットのキーで登録されていたため、旧部屋に入れるようになる。旧部屋には一覧が無いので、削除の対象にならず、残る。
- 共同編集は出荷前の機能で、本番に実データは無い、という前提。この前提は、デプロイ前に確認する(本番の `DOCUMENT_ROOM` は列挙できないので、利用者への確認で行う)。

## 既知の残り(別カードで管理)

- 変更より前に保存された期限なしの `snapshot:` / `actions:`。持ち主を辿れず、この変更では消えない。本番には8件(2026-10-09、読み取りのみで確認)。
- 旧部屋(上記)の掃除。
- アカウントを統合する前の別名のキーで作った部屋は、削除が辿れない(チャットも同じ制約)。
- 招待と退会が競合すると、削除済みのアカウントのキーで席が作られうる。同じ sub で再登録すると同じキーになり、同意なしで参加者に戻る。
- 参加者のキーが、他の参加者に見える(`participants`、提案の `authorKey`)。以前はサインインごとに変わっていたが、今は固定で、部屋をまたいだ相関ができる。
- 空にした部屋の Durable Object のストレージ自体は消していない。表の行を消すのみ。
