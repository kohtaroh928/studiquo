# ADR-0004 アカウント削除で、学習スナップショットと共同編集ノートも消す

## 背景

プライバシーポリシーは、アカウントを削除すると端末とクラウド上の学習資料などを削除すると書いている。独立レビュー(2026-10-09、main `50c34d9`)で、次の2種類が削除後も残ると指摘され、コードで確認した。

1. **学習スナップショット(`snapshot:<トークンのハッシュ>`、`actions:<トークンのハッシュ>`)**: 期限なしで保存していた。削除は、現存するセッション行から所有トークンを割り出して消す。セッション行は90日で消えるので、古いトークンのスナップショットは持ち主を辿れず、残り続ける。
2. **共同編集ノート(`DOCUMENT_ROOM`)**: 削除の処理が一度も参照していなかった。さらに、部屋の参加者を**セッションのトークンのハッシュ**で記録していたため、サインインし直すと持ち主が自分の部屋に入れず、招待された人(アカウント固有のチャットのキーで登録)は一致せず入れなかった。

## 決定

- **スナップショットと保留中の操作**: トークンのハッシュで保存するものには、そのトークンのセッションの残り日数を有効期限として付ける(`remainingValiditySeconds`)。セッションと一緒に消えるので、削除が辿れない取り残しは生じない。アカウント単位のコピー(`snapshot:<アカウントのハッシュ>`)は期限なしで、削除時に消す(従来どおり)。
- **共同編集ノートの参加者**: セッションごとのキーをやめ、チャットと同じ、アカウントごとに変わらないキー(`resolveChatUserKey`)で記録する。招待(友達コードから引くキー)と同じ名前空間になる。
- **削除時の探し方**: 部屋の作成と招待のとき、`doc-room:<参加者のキー>:<部屋ID>` に役割を書く。削除は、このキーの一覧から部屋を探す。
  - 持ち主の部屋は丸ごと消す(本文、提案、参加者)。参加していた他の人の一覧のキーも消す。
  - 招待されただけの部屋では、その人の席と、その人が出した未決の提案だけを消す。承認済みの文章は、持ち主の文書の一部として残る。最後の1人が抜けた部屋は消す。
  - 途中で失敗しても、再実行で完了する。部屋の消去は空に対しても安全で、一覧のキーは、部屋の処理が済んでから消す。

## 採らなかった案

- 全件を走査して持ち主を探す案: 退会の処理量がユーザー数に比例する(既知のM-7)のを悪化させる。
- ポリシーの文面を弱める案(方針2): 利用者の期待に反するので採らない。

## 互換性

- アプリ側の変更は不要。リクエストの形は変わらない。
- **この変更より前に作られた部屋**は、持ち主がトークンのハッシュで記録されているため、以後はアクセスできない(削除の対象にもならない)。もともと、サインインし直すと持ち主が入れない状態だった。共同編集は、出荷前の機能として扱う。

## 既知の残り

- この変更より前に保存された期限なしの `snapshot:` / `actions:` は、持ち主を辿れず、この変更では消えない。本番に実利用者がいる場合は、一度きりの掃除が必要(下の確認方法で件数を見る)。
- 掃除の確認: 本番のKVに対して `wrangler kv key list --prefix snapshot: --namespace-id <id>` で件数を見る(読み取りのみ)。
