# ADR-0003 ログインの待機・混雑を、パスワード違いと区別して扱う

## 決定

- メールとパスワードのハッシュはArgon2id(m=19MiB, t=2, p=1、OWASPの最小構成)にする。
- ハッシュ処理は同時2、待ち32まで。満杯のときは、ハッシュも照合もせずに503(`Retry-After: 2`)を返し、この試行は失敗として数えない。
- 既知の端末(信頼済みの組)には予備枠16を残し、満杯でもログインを通す。
- 失敗の連続による待機の429と、混雑の503は、アプリ上でパスワード違いとは別の文言で表示する。確認コードの429は専用の文言にする。
- 待機は自動で解けるようにし、アカウントのロックはしない。

## 採らなかった案(docsに書かれていること)

- **IPごとの同時実行の制限**: 共有IP(学校など)の正規の学生が429になる副作用に対し、効果が小さいので採用していない。

## 既知の弱点(docsに書かれていること)

- 待ち行列はWorkerのインスタンスごとにある。偽のメールで満杯にされると、そのインスタンスで新しい端末・回線からのログインが503になる。既知の端末は予備枠で通る。
- 攻撃者が自分の無料アカウントで多数のIPを信頼済みにすると、予備枠を埋められる。通常の枠だけの状態に戻るだけである。
- 待機は他人に起こされうる。標的のメールに失敗を重ねると、その人は新しい端末・回線から最大15分の待機を受ける。
- 確認コードの429は、サーバーが`Retry-After`を返さないため、アプリは時間を言わずに案内する。

## 関連コミット

- `56cc1fa` ログインの429と503を、パスワード違いとは別の文言で表示する
- `b037cd0` 確認コードの429を専用の文言にし、漏えいパスワードの拒否後はコード画面で入れ直せるようにする
- `8d2bbdb` Argon2idの待ち行列が満杯でも、既知の端末からのログインは通す
