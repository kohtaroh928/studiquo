# ADR-0002 AIの提供先をGoogle一社に限定し、同意と承認のゲートを置く

## 決定

- AIの初期提供先をGoogleのみにする。旧モデル定義は内部に残るが、アプリの選択肢と公開API境界で制限し、direct Anthropic経路は拒否する。
- AIへ送る前に、送信内容を説明し、バージョン付きの許可を必須にする。拒否しても、通常のノート機能は使える。
- 開いているノートを自動送信しない。送るのは、質問・会話履歴と、利用者が選んだ資料だけにする。
- 翌日AI復習と自動診断は初期OFFにする。旧版の設定を新しい許可へ自動移行しない。
- 提供条件の確認が済むまで、サーバー側の`AI_PROVIDER_APPROVED=false`を維持し、AIを停止する。

## 改定(2026-10-09): ChatGPT契約者の「持ち込み利用枠」を、条件付きで認める

上の「決定」は、**Studiquoが費用を負担して提供するAI**(以下、標準提供)に引き続き適用する。標準提供の提供先はGoogleのみで、変えない。
そのうえで、次の別枠を追加する。

- **持ち込み利用枠**: 利用者自身のChatGPT契約(Go/Plus/Pro)の利用枠を、「Sign in with ChatGPT」でStudiquoのAIチャットから使えるようにする。費用は利用者のChatGPT契約が負担し、Studiquoは負担しない。
- **Studiquoのプラン制は残す。** 持ち込み利用枠は、プランの代わりではなく、プランに足せる選択肢とする。ChatGPT契約を持たない人、使いたくない人は、今まで通りStudiquoのプランで使う。
- 持ち込み利用枠は**利用者が自分で有効にする任意機能**で、初期はOFFにする。標準提供の有無や、通常のノート機能には影響させない。
- 標準提供のゲートは、持ち込み利用枠にも**そのまま適用する**。具体的には、送信内容の説明とバージョン付きの許可(提供先ごとに別々に取る)、ノートの自動送信なし、サーバー側の承認フラグによる停止である。承認フラグは、標準提供(`AI_PROVIDER_APPROVED`)とは別に、持ち込み利用枠用を新設する(名前は設計時に決める)。
- **Claudeは対象外のまま。** Anthropicの規約がサブスク資格情報の第三者利用を禁じており、APIキー方式のみ可のため、持ち込み利用枠には含めない。公式の仕組みが出た時点で再検討する。

### 持ち込み利用枠を公開する前提条件

次のすべてを満たすまで、持ち込み利用枠は公開しない。

1. OpenAIの商用パートナー承認が下りている(2026-09-29発表の限定トライアルは承認制)。
2. 標準提供側のGemini提供条件の確認が済み、AIの公開が済んでいる(上記の未完了項目)。
3. OpenAI側の対象年齢・学生向け提供可否・訓練利用・保存期間を確認し、プライバシーポリシーとApp Storeのプライバシー申告に反映している。
4. 借りたトークンの保管場所(Worker側を推奨)・更新・連携解除・アカウント削除時の消去を設計し、ADR-0004の削除対象に加えている。
5. Highリスク変更として、安全確認、ロールバック手段(承認フラグでの停止)、独立レビューを済ませている。

### 持ち込み利用枠の扱いで決めること(設計時に確定)

- 利用枠を使い切った、またはログインが切れたときに、自動でStudiquoのプランへ切り替えるか、利用者に選ばせるか。**自動切替は費用が利用者の意図なくStudiquo側に移るため、既定は「選ばせる」とする(案)。**
- プラン別の利用上限と、持ち込み利用枠の使用量を、どう数えるか(持ち込み分はプランの上限に数えない案)。

## 根拠(docsに書かれていること)

- 学生・未成年者への提供可否、契約、モデル訓練利用の有無、保存期間が未確認である。
- 旧アプリには新しい同意ヘッダーがないため、新Workerは旧アプリからのAI送信を拒否する。通常の学習機能は継続できる。
- 異常時は、承認フラグをfalseに戻せば止められる。

## 未記入(自分で補う)

- Googleを一社目に選んだ理由(Anthropic、OpenAIを後回しにした理由)。
- 他の提供先を追加するときの条件(標準提供の場合)。案として、持ち込み利用枠の前提条件(上記の2〜5)と同じ確認を、提供先ごとに済ませることを置く。採否は自分で決める。
