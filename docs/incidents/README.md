# 対応記録(incidents)

事故・障害・セキュリティ上の事象ごとに、1件1ファイルでここに記録する。手順そのものは[RUNBOOK](../RUNBOOK.md)、記録の項目は[TEMPLATE.md](TEMPLATE.md)。

## ルール

- ファイル名は `YYYY-MM-DD-識別名.md`(日付は検知した日、日本時間)。雛形をコピーして作る。
- **Gitに置かない**もの: 個人情報、利用者のメールアドレス・ID、トークン・鍵、学習内容、スクリーンショットなどの証拠そのもの。公開できない証拠は、アクセス制限した非公開の保管先に置き、ここには**安全な参照(場所の名前と日付)だけ**を書く。
- 原因が確定していないものは「仮説」と明記する。誰かの注意不足だけで原因分析を終えない。再発防止には、再現テスト・監視・権限や容量の改善などを選び、担当と期限を付ける。
- 記録を作ったら、GitHub Projectの[Studiquo タスク](https://github.com/users/kohtaroh928/projects/1)に未了の再発防止を項目で残し、記録からカードへ、カードからこの記録へ相互に参照する。
- 通知義務の確認は[RB-19](../RUNBOOK.md#rb-19-通知義務の確認項目責任者が専門家に確認する)を使う。

## 机上訓練

[drills/](drills/)に3つのシナリオがある。実施したら、結果を `drills/YYYY-MM-DD-実施記録.md` に書く(誰が、何分で止められたか、手順の抜け)。実施記録の見つかった抜けは、RUNBOOKを直す。
