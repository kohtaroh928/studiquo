# 訓練2: 確認コードの悪用(メール送信の連打)

## 状況
Resendから「送信数が通常の50倍です」「バウンス率が上昇しています」という通知が届く。Slackの問題報告チャンネルには何も出ていない。`/api/auth/email/send-code` が、多数のアドレスに向けて呼ばれている可能性がある。

## 確認していくこと
1. まず止める手段は。(RB-18の表: `DISABLED_FEATURES="email"`、WAFで該当のネットワークを制限、Resendのキー失効)
2. `email` を止めると利用者に何が起きるか。(新規登録・ログインの確認コードが届かない。RB-04)。止めずに済む軽い手段はあるか。(WAFの上限)
3. 悪用が誰のアドレスに送られたかを、個人情報を広げずにどう調べるか。(ログの件数、国・ASN。アドレスは見ない)
4. 送信元ドメインの評判(バウンス率)が落ちた場合、どう戻すか。(Resendの案内、送信の再開時期)
5. 通知義務はあるか。(他人宛にコードを送らされただけで、情報は漏れていない。RB-19で確認)
6. 再発防止は。(アドレスごと・IPごとの上限の見直し、Turnstile等の導入の判断、アラート[MONITORING.md])
