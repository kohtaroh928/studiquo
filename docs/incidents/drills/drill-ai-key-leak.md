# 訓練1: AIキー(OpenAI)の漏えい

## 状況
月曜の朝、OpenAIから「利用額が月の上限の80%に達しました」という通知が届く。前週の同じ時点の利用額は10%だった。公開リポジトリの履歴を検索すると、過去のコミットに `sk-` で始まる文字列が見つかる。

## 確認していくこと(進行役が順に聞く)
1. 今この瞬間に、被害を止める手段は何か。誰が操作できるか。(RB-18の表。OpenAIのキー失効、`AI_PROVIDER_APPROVED="false"`)
2. キーを失効すると、利用者には何が起きるか。復旧までのAI機能の案内はどうするか。(RB第7章)
3. 新しいキーを入れる手順は。ステージングで先に確かめるか。(付録A-1、A-3)
4. 漏れたキーで何ができたか。過去の利用ログから、いつから使われたかをどう調べるか。(OpenAIの利用履歴。個人情報は取らない)
5. 履歴からキーを消す必要があるか。消しても失効の代わりにならない理由は。(RB-10「避ける操作」)
6. 通知義務はあるか。(キーの漏えいだけでは利用者の個人情報は漏れていない。ただし、AIに送った学習内容がキーの持ち主以外に見えたかは確認項目。RB-19)
7. 再発防止は。(コミット前の秘密スキャン、OpenAI側の利用上限、アラート[MONITORING.md])

## 抜けを見つけるための問い
- OpenAIの利用上限は設定してあるか。通知は誰に届くか。
- 失効の権限はOpenAIのアカウントの誰が持っているか。その人が不在のときは。
