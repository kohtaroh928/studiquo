## 事前に決めた成功基準

「答えなし」の基準は`status`が`insufficient`（または`partial`ではなく停止）になること。「答えあり」の基準は、`on`で`grounded`のまま正解の位置を引けていること（`evidenceRecall`が`off`相当と同じ）。基準は次のとおり。1つでも満たさなければ「しきい値は不採用または要調整」と報告する。

| # | 基準 | 合格 |
|---|---|---|
| M1 | 答えありの**誤停止**（`on`で`insufficient`になった答えあり）。分母は単一主題の答えあり56 | **0件**。1件でも出れば不合格 |
| M2 | 比較・2主題の答えあり18の**停止** | **0件**（設計上、停止しない。実装の確認） |
| M3 | 答えありの**降格**（`on`で`grounded`→`partial`）。74問全体 | 74問の**5%（3問）以下**。ただし誤停止が0でも降格が多い場合は、その内訳を報告する |
| M4 | 答えなし（比較・2主題の形5問を除く40問）のうち、`shadow`で通っていた質問の**新たに止まった率** | 通っていた質問のうち**20%以上**が止まる（効果あり）。10%未満なら「効果は小さい」 |
| M5 | 判定の失敗（タイムアウト、モデル失敗、確率なし）の割合 | 失敗は`keep`（通す）になる設計。失敗が**5%以下**。超えれば報告する |

補助の指標（合否には使わない）：確率の分布（答えあり・答えなし別）、0.25付近（0.15〜0.35）の質問の件数、種類ごとの停止率、1問あたりの追加のAI呼び出し数、遅延。

## 解釈の規則（実行前に決める）

1. 結果が基準を満たさなくても、**しきい値を調整して同じ質問で再測定しない**。調整したい場合は、結果を報告し、新しい質問を別に作る。同じ質問で調整した場合、その質問は「調整済み」と書き、独立の検証にならないと明記する。
2. M1が不合格なら、`RAG_JUDGE=on`は推奨しない。`shadow`の継続を勧める。
3. 効果（M4）は、答えなしの種類ごとに分けて報告する。どの種類で効くか、効かないかを隠さない。
4. 「判定の導入前」は、`shadow`の結果（結果は`off`と同じことを実装時に確認済み）を基準にする。
5. 質問文・正解の位置・回答の本文は記録しない。記録は、質問のid、種類、`status`、確率の10%刻みの帯、停止／降格の有無だけ。
6. 測定は1回ずつ。同じ質問で偶然が混じる可能性（埋め込みの揺れ、リランクの順位）があるため、境界上の1問の差は有意とは言わない。

## 限界（実行前に分かっているもの）

- 1つの資料（気象庁の教科書）だけ。ほかの分野・言語・資料の形式には一般化できない。
- 質問は私が作った。答えなしの語の不在は確認したが、資料の別の場所に答えが言い換えで書かれている可能性は、完全には排除できない（正解の位置の確認は答えありのみ）。
- 検索の索引は実埋め込みだが、D1／Vectorizeはローカル代替（既存の評価と同じ）。本番の検索と細部が違う可能性がある。
- 「答えあり」の回答の質（最終回答の内容）は測らない。測るのは検索の段階の状態（停止・降格）だけ。
