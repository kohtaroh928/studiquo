# Hybrid RAG v1

## Contract and rollout

The AIProvider → WorkerAIProvider → Worker path remains; answer generation now uses OpenAI Responses API. Standard defaults to Luna (`openai-luna` → `OPENAI_LUNA_MODEL=gpt-6-luna`).
RAG is opt-in, and `RAG_ENABLED=false` is the initial production and staging
setting. Ordinary chat requires the new `openai-v1` AI consent and an adult/teen age band. Indexing and
RAG chat additionally require `X-Studiquo-RAG-Consent: rag-openai-v1`, explaining
Cloudflare inference and persistent text/embedding storage. Deletion remains
available while retrieval is disabled.

The API authentication boundary resolves Bearer tokens through `realSession()`;
body account IDs are never used. Worker-derived, domain-separated SHA-256
account keys scope every SQL read and vector query. Vector matches are hydrated
from D1 under the same owner/scope; metadata is never trusted as content.

## Acceptance and threat model

- Upload 100 PDF pages in 5–10 page requests, never crossing page boundaries.
- Target child chunks approximately 300–500 tokens, overlap approximately
  50–80 tokens. Counts are estimates, not the BGE tokenizer's exact counts.
- Page parents, semantic paragraph/sentence boundaries and Japanese searchable
  normalized text preserve structure and page citations.
- PDF source hashes and notebook page hashes avoid repeated embeddings when
  index format and context are unchanged. Index format v2 adds title/headings;
  embedding-input hashes prevent reuse across title/heading/format changes.
- Query Vector Top20 and FTS5 BM25 Top20 concurrently, RRF Top15 with comparison coverage, rank-fused rerank Top5
  with `@cf/baai/bge-reranker-base`; embedding v1 is
  `@cf/baai/bge-m3`, 1024 dimensions, cosine.
- Current page / notebook / folder / library scopes apply to all retrieved
  content including neighbors. Only ambiguous questions use history expansion;
  only comparison/composite questions use bounded multi query.
- RAG excerpts are supplied to allowed OpenAI models only under renewed rag-openai-v1 consent.
  Disabled/unconsented RAG preserves ordinary OpenAI chat.
- RAG outage or no matches yields ordinary chat. Reranker failure preserves RRF.
- Citations are structured retrieval facts (`sourceId`, `title`, `pageNumber`,
  `chunkId`), never generated by the LLM. Page numbers are one-based.
- Locked notebooks never upload; locking/deleting indexed notebooks removes
  their cloud index, with retry handling for offline failures.
- Prompt injection remains untrusted reference text. Delimiters are escaped;
  instructions prohibit acting on retrieved instructions. This mitigates rather
  than guarantees immunity to LLM prompt injection.
- Never log document content, queries, prompts, embeddings or provider exception
  bodies. Size limits apply to actual streamed bytes, not Content-Length alone.
- Deletion keeps D1 IDs until Vectorize deletion is acknowledged; D1/FTS then
  delete together. Account erasure does not depend on the enable flag.

## Registration readiness (2026-10-09, staging deployed)

Upload completion does not imply Vectorize query visibility. The additive authenticated
`GET /api/rag/sources/:sourceId/readiness` endpoint checks D1 completion and leases,
up to 1,000 current chunk IDs and vector metadata in batches of 20, one accountKey/sourceId/folderId
filtered query, and an unchanged D1 snapshot before returning `ready`. It exposes
no document text, embeddings, account keys or chunk IDs. It shares the existing
registration rate limiter and adds no AI inference, binding or migration.

`ready` confirms current vector ID visibility and source-level search availability;
it does not certify every chunk's ANN visibility or answer quality. Over 1,000 chunks
remain unconfirmed, with an explicit UI check-limit explanation.

The iOS controls distinguish uploading, waiting, ready and failure, with separate
missing/empty/disabled/limit states. Foreground checks run every 10 seconds for up to
18 attempts, can be stopped, and never reupload text. Unknown replies, old Workers
(404), revision mismatch and timeouts do not imply readiness. Account/consent/source
changes and cancelled operations cannot publish stale success. OCR review notices
remain separate. A new app remains compatible with an old Worker by showing waiting.

Production remains disabled. Staging deployment and synthetic 100-page live validation

`source_only` keeps the existing document-only instructions;

## Automatic-library safety foundation (2026-10-11, local only)

Migration `0008_rag_control.sql` adds permanent managed-account consent epochs, stable document eligibility and generation CAS, source cleanup jobs and a vector write-ahead journal. `RAG_AUTO_INDEX_ENABLED=false` is the initial setting in production and staging configuration. No additional binding, secret, model or Vectorize index is required. The existing account-keyed registration rate binding also limits the new control APIs.

New authenticated APIs (all under `/api/rag/`):

- `GET consent`: managed state, enabled state and current consentEpoch.
- `POST consent`: `{enabled, expectedEpoch}`. Enabling requires both RAG flags. Every accepted change increments the epoch and invalidates old sources. Calling this protocol permanently upgrades the account and retires previous manual indexes. The future UI must disclose this transition.
- `POST documents/prepare`: `{documentId, requestId, expectedGeneration, consentEpoch, sourceHash, title, folderId, totalPages}`. Returns a server-issued `{sourceId, documentId, generation, consentEpoch}`. Exact request retries return the same result.
- `POST documents/:documentId/state`: `{state, expectedGeneration, consentEpoch}`. Allowed states: eligible, locked, excluded, trashed, deleted. Restoration is explicit; deleted is terminal. Unknown documents can be tombstoned before a delayed upload arrives.
- Existing `POST index`: normal PDF batches plus `control` containing the prepare response. Metadata must match the prepared generation. Managed accounts cannot use legacy payloads or client-selected replacement source IDs.
- `POST cleanup`: bounded owner-scoped retry; works while flags are disabled. Existing every-hour scheduled handler also retries cleanup.
