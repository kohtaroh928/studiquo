# 判定器しきい値の汎化検証：方針（事前登録の前段）

2026-10-25。**方針の整理のみ。測定はしていない。** 資料の選定・質問の作成・実行前登録は、この方針に基づいて別に行う。

## 1. 何を決めるための検証か

判定器（`rag/judge.ts`、`@cf/cloudflare/clef-flash`）のしきい値 `stopBelow` 0.25 / `partialBelow` 0.5 が、**見たことのない資料と質問でも**使えるかを決める。しきい値は**この検証では動かさない**。動かす・動かさないの判断材料を作るのが目的である。

きっかけ：第2資料（国土地理院の地理教材、29問の答えあり）の探索評価で、`on` のとき答えありの 3/29（10.3%）が `grounded` から `partial` に下がった。確率は 0.273・0.397・0.499。期待根拠は3問とも取得済みで、判定器だけが自信を持てなかった。同じ抜粋なら確率は完全に同じ（決定的）で、実行の揺れではない。

新しい公開資料を **2冊以上**。次の条件を満たす。

- 既存の全評価で使っていない。分野が既存（気象・地理・合成）と離れている。

## 5. 質問

1冊あたり、答えあり 60 以上・答えなし 30 以上（2冊で 180 以上）。

### 5.1 答えあり（60以上）

| 型 | 件数の目安 | 備考 |
|---|---|---|
| 直接・言い換え・数値などの単一主題 | 40 | 見出しのみのページ、短いページ、2段組のページを意図的に含める |
| 比較・2主題 | 20 | 言い回しを変える（下の型を各2問以上）。主題抽出の検証（案C）を兼ねる |

比較・2主題の言い回しの型：「AとBは、それぞれ…」「AとBでは、…どのような違い」「AとBの違い」「AとBを比較して」「AはBと何が違う」「AとB、どちらが…」「AとBの共通点」「Aの特徴とBの特徴」「AとBとCは、それぞれ」（3主題）「Aとは、…。Bとの違い」（定義の導入つき）。述語に属性が入る形（「水と油の特徴は」）、述語に別の名詞が入る形（「…昼と夜でどう違う」）も含める。

### 5.2 答えなし（30以上）

話題は合うが詳細がない、単位つきの数量がない、無関係、資料にない固有語、同じ話題で対象が別、の5型を各5〜6問。

### 5.3 作り方の規則

- **質問は、検索結果とコードを見る前に確定する。** 作成後に変更・除外しない。信頼性が疑わしい項目は、除外せず注記する。
- 正解の位置（ページと原文の一致箇所）をプログラムで確認する（答えありは部分文字列の一致、答えなしは抽出本文でのキーワードの不在）。
- **作成者を分ける。** 質問を作る担当は、判定器・主題抽出のコードの挙動を見ていない担当（あなた、または別のモデルが、このコードを読まずに作る）が望ましい。同一作業者が作る場合は限界として明記する。
- 質問と本文はリポジトリに入れない。`~/.studiquo-private/rag-<資料名>-v1/` に保存し、manifest の SHA-256 だけを文書に記録する。
- 各質問に型のラベルを付ける（集計で型別の結果を出すため）。

## 6. 実行

- 資料ごとに `shadow`（結果は変えず確率を記録）と `on`（実際に停止・降格）を、**各1回**。
- 揺れの幅の確認（元の案B）：各資料から30問を選び、`shadow` と `on` をさらに**2回**ずつ繰り返す。確率の同一性（判定器の決定性）と、`status` が変わった質問の数を報告する。
- 呼び出し上限（`real-material-evaluate.ts` は最大500回）のため、約30問ずつの組に分ける。v7 と同じ方式。
- 使用量（neurons、呼び出し数）を記録する。本文・質問文・秘密は結果に残さない。
- 実行環境は従来どおり（ローカルFTS5・コサイン検索の代替＋実際のWorkers AI）。**最終回答の生成、実Vectorize、PDF取り込み、iPad実機は測らない。**

## 7. 事前に決める成功基準

2冊をまとめた値を主、資料別を従とする。割合には Wilson 95%区間を併記する。

| # | 基準 | 合格 |
|---|---|---|
| V1 | 単一主題の答えありの**誤停止**（`on` で `insufficient`） | **0件**（まとめて 80 問以上あれば、上限の目安は約 4.6%） |
| V2 | 比較・2主題の答えありの**停止** | **0件** |
| V3 | 答えあり全体の**降格**（`grounded`→`partial`、判定が原因のもの） | **8%以下**で合格、**5%以下**なら良好。区間の上限も報告し、上限が 15% を超えるなら「判定不能」とする |
| V4 | 答えなしのうち、`shadow` で出典が付いたものが `on` で止まる割合 | 20%以上で効果あり、10%未満は効果が小さい。あわせて、答えなし全体の出典なしが 80%以上 |
| V5 | 判定の失敗（タイムアウト・形式不正・確率なし）の割合 | 5%以下。失敗は `keep`（通す） |
| V6 | **近接帯：** 答えありのうち、確率が 0.25 以上 0.30 未満の質問の割合 | 参考値。**3% を超えたら「停止に近い」として脆弱と判定**し、V1 が合格でも `on` を有効にしない |
| V7 | 繰り返しの揺れ | 同じ抜粋なら確率は一致する。`status` が変わる質問は 5% 以下 |
| V8（任意） | 降格された答えありについて、最終回答が `partial` の指示で実際に悪くなるか | 該当質問を最大10問、最終回答を生成して人が確認。有料のAPI呼び出しが発生するため、**別途承認** |

V1・V2・V5 のどれかが不合格なら全体不合格。V3・V4・V6・V7 は §8 の規則で扱う。

## 8. 結果ごとの方針（実行前に決める）

| 結果 | 方針 |
