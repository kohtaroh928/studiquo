# 分割画面の資料選択: 並べ方の切り替え

## 目的と範囲

ノートの2分割を押すと開く資料選択画面(`SplitSourcePicker`)で、資料の並べ方を「リスト・アイコン・カラム」から選べるようにする。画面は横長にし、カラムが収まらない場合は横スクロールで見られるようにする(ホーム画面のカラム表示と同じ考え方)。リスクはStandard。保存データ、API、サーバー、権限には触れない。

## 受け入れ条件

- 画面上部(タイトルの下)に「リスト」「アイコン」「カラム」の3ボタンがあり、押すと資料がその並べ方に切り替わる。選んだ並べ方は次回も保持する。初期値はリスト。
- どの並べ方でも、資料は種類(ノート・PDF・暗記カード)ごとに分かれる。ゴミ箱のものは出さない。
- リスト: 種類ごとの見出しの下に縦の行(従来どおり)。
- アイコン: 種類ごとの見出しの下に、タイルを敷き詰めたグリッド。
- カラム: ホーム画面と同じフォルダ階層。最上位の列に、最上位のフォルダと資料(ノート・PDF・暗記カード)が並び、フォルダを開くと右に列が増える。列が画面に収まらないときは横スクロールで見られ、新しい列まで自動でスクロールする。各列は縦にもスクロールできる。
- 資料を選ぶと、並べ方に関係なく従来と同じ処理(分割して開く)が呼ばれる。表示中のノートは「表示中」と示す。
- 新規作成、キャンセル、検索欄の挙動は変えない。
- 画面はiPadで横長(`FixedSheetSize(.page)`。iOS 17では最大のdetent)で開く。

## 設計

- 新規ファイル `studiquo/Views/SplitSourcePicker.swift` に、`NoteEditorView.swift`内のprivateな`SplitSourcePicker`を移す。呼び出し側のシグネチャは変えない。
- 並べ替えと分類のロジックは`SplitSourceCatalog.groups(...)`の純関数にして、ユニットテストできるようにする。
- 資料のIDは`PersistentIdentifier`(SwiftDataが各モデルに持たせる恒久的な識別子)にする。
- 並べ方は`@AppStorage("splitSourcePickerLayout")`に保存する。未知の値はリストに戻す。
- 並べ方の切り替えは、UIテストで確実に押せるよう、アクセシビリティ識別子付きのボタン3つで作る(`split-source-layout-list|icon|column`)。
- 前提としたこと: 「PDFの種類で分ける」は、ノート・PDF・暗記カードという種類のこととして扱う(従来は「ノート・PDF」が1つだった。今回はノートとPDFも分ける)。カラムはホーム画面と同じフォルダ階層とする(フォルダの正本はホームと同じ`folderName`のパス。`Folder`オブジェクトのないパスや親フォルダも列として辿れるようにする)。

- 挙動の変更点: 暗記カードもゴミ箱のものは出さない(従来は出ていた)。

## 互換性・リスク

保存形式の変更なし。`UserDefaults`に新しいキーを1つ追加するだけで、削除すれば初期値に戻る。ロールバックはこのブランチの取り消しのみ。

## 検証

- ユニットテスト: 種類ごとの分類、ゴミ箱の除外、表示中の判定、保存値の復元。
- UIテスト: 3つの並べ方の切り替え、資料の選択、フォルダを開くとカラムが増えること、カラムの横スクロール、新規ノート・新規暗記カードの作成(名前あり・なし)、作成アラートとシートのキャンセル。
