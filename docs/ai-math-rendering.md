# AIの出力の数式を読みやすく表示する

## 問題
AIは数式をLaTeX(`$\frac{a}{b}$`、`x^{2}`)で、書式をMarkdown(`**太字**`、`## 見出し`)で返す。
アプリはそれを加工せずに表示するため、記号がそのまま画面に出て読みづらい。

原因は3つ:
1. サーバーの指示文(`mcp-server/src/ai.js` の `CHAT_SYSTEM` など)に、数式・書式の指定がない。
2. 返答を `Text(message.text)` でそのまま表示している(`Views/AIChatView.swift` の `AIChatBubble`)。
3. 既存の `MathExpression` は小さな部分集合(分数・累乗・添字・根号・ギリシャ文字)で、AIの出力には足りない。
   未対応のコマンドは名前がそのまま出る(`\left` → 「left」)。

## 方針(A・B・C をすべて実装する)
- **A** AIへの指示: 数式を `$…$`(行内)と `$$…$$`(独立した行)で書かせる。
- **B** 読みやすいテキストへの変換: LaTeXを `x²`、`(a+b)/2`、`Σ` などの文字にする。
  コピー、「ページに貼り付け」、VoiceOver、通知、描画に失敗したときの代替表示に使う。
- **C** 本格的な組版: SwiftMath(MIT)で数式を描画する。Markdownは自前で段落に分けて組み立てる。

保存データは変えない。変換と描画は表示時にだけ行う(過去の会話にも効く)。

## 現状の見た目(基準)
返答に `## 二次関数の最大・最小`、`$y=-2x^2+8x-3$`、`**$x=2$ のとき最大値 $5$**`、
`$x=-\frac{b}{2a}$` がそのまま出る。

## ステップ1(試作)の結果
**判定: 続行(GO)。** SwiftMath で日本語まじりの式を、実用的な品質で組版できる。

### 確認できたこと
- **見た目**: 日本語の文章の途中に式を混ぜても、字形・行の高さ・折り返しが良好(日本語はCJK対応の折り返し。
  文字の代替フォントは `Hiragino Sans` を設定)。分数、根号、総和・積分の上下限、行列(`pmatrix`)、
  場合分け(`cases`)、整列(`aligned`)、`	ext{日本語}` を含む分数が正しく描画される。
- **対応状況**: サンプル集の式199個のうち184個(92%)が解析できる。解析できない15個のうち11個は
  わざと入れた未対応のサンプル。想定外は `\therefore` `\because` `\blacksquare` `\hline` の4種で、変換の表で補える。
- **生成の途中状態**: すべての接頭辞(3216個)でクラッシュなし。約4分の1は解析できず、完成するまで文字のまま表示する。
- **極端な幅(0〜4000)**: クラッシュなし。
- **性能**: 1行あたり約0.4ミリ秒。300行で約120ミリ秒。生成中も、デルタごとの再描画が可能。

### 設計に反映する注意点
1. **未対応の式は、エラーになるだけでなく、何も描画されない(空白になる)。** 描画の前に必ず解析して、
   失敗したらステップ2のテキストで代替表示する。
2. **ライブラリは `main` のコミット(`1d2c908`)に固定する。** 最新のリリース(1.7.2)には、行の折り返しがなく、
   1.7.3のタグは取得できない(`project.yml` にコメントあり)。更新は手動で確認する。
3. **変換の表を持つ**: `\therefore`→∴、`\because`→∵、`\blacksquare`→■、`\hline` は除く、
   `\boxed` `\underbrace` などは文字で代替。
4. **部品は「提案された幅いっぱい」を返す**(内容の幅を返すと、外側で中央に置かれる)。
5. **文章中のバックスラッシュ**: `\text{}` の中では書けない。コードとMarkdownは、SwiftMathを通さず、
   SwiftUIの文字(等幅)で表示する。
6. **複数行の式**(`\begin{align*}` が `$$` なしで書かれる)は、1つの独立した式として切り出す。
7. **行内の式は、狭い幅では式の途中で折り返す**(括弧の中など)。許容範囲だが、気になれば調整する。
8. アプリは全体がライトモード固定(`StudiquoApp.swift` の `.preferredColorScheme(.light)`)。
   色は環境から取る形にしておき、ダークモード対応が必要になったときに備える。

## ステップ2(読みやすいテキストへの変換)の結果
実装: `Services/MathSegmenter.swift`(区切りの切り出し)、`Services/MathTextFormatter.swift`(変換)、
`Services/MathSymbols.swift`(記号の表)。

### 使い方
- `MathSegmenter.segments(in:)`: 文章を `text / inlineMath / displayMath / code / incomplete` に分ける。
  ステップ3以降の構造の分解と描画の入力にもなる。
- `MathTextFormatter.readableMath(from:)`: 1つの式(区切りなし)を読みやすいテキストにする。
- `MathTextFormatter.readableText(from:)`: 返答全体の数式だけを変換(Markdownの記号はそのまま)。
- `MathTextFormatter.plainText(from:)`: さらにMarkdownの記号(`**`、`##`、`- `、表、リンク)も取る。
  コピー、ページへの貼り付け、VoiceOver、通知、描画に失敗したときの代替表示で使う。

### 変換の例
`x^2+y^2=r^2` → `x² + y² = r²` / `\frac{a+b}{2}` → `(a + b)/2` / `\sqrt{b^2-4ac}` → `√(b² − 4ac)` /
`\sum_{k=1}^{n}` → `Σ(k = 1〜n)` / `\int_0^1 x^2\,dx` → `∫₀¹ x² dx` / `\binom{n}{k}` → `ₙCₖ` /
`\mathbb{R}` → `ℝ` / `\begin{pmatrix}1&2\\3&4\end{pmatrix}` → `(1, 2; 3, 4)` / `\ce{H2O}` → `H₂O`

### 守っていること
- コードブロックとインラインコードは変換しない。`$100`、`$HOME`、`\$` は式にしない。
- 返答が生成の途中で、閉じていない式は、そのまま残す(`incomplete`)。すべての途中状態でクラッシュしない。
- 未対応のコマンドは消さない(`\name(引数)` の形で残す)。
- 曖昧になる所は括弧を付ける(`(a + b)/2`、`1/(2a)`、`√(x²)`、`e^(−x²)`)。
- 1回の変換は、約1500文字の返答で約4ミリ秒(シミュレータでの実測。20ミリ秒以内を保証するテストあり)。
  生成中に毎回変換しても問題ない速さだが、ステップ5では、変わった吹き出しだけを変換する。

### サンプル集に対する確認
- 変換後に、`\command` が残らない(コード・未対応のサンプルを除く)。`$` も残らない。
- 価格・シェル変数・すでに読める文字は変わらない。変換は冪等(2回かけても同じ)。

## ステップ3(文章の構造の分解)の結果
実装: `Services/RichTextParser.swift`。`RichTextParser.parse(_:) -> [RichBlock]`。

### 出力の形
- ブロック(`RichBlock`): 見出し、段落、独立した式、**閉じていない独立した式**、コードブロック(言語・閉じているか)、
  箇条書き/番号付き(入れ子・開始番号)、引用、表、区切り線。
- 行内(`RichSpan`): 文章、行内の式、行内コード。それぞれに、太字・斜体・取り消し線・リンクの属性が付く。

### 仕組み
1. `MathSegmenter`(ステップ2)で、式とコードを取り出し、見えない目印(私用領域の文字)に置き換える。
   行単位のMarkdownの解析が、式の中の `|` `*` `_` に惑わされない。
2. 行単位で、ブロックを解析する(再帰: 引用と箇条書きの中身も同じ解析器)。
3. 行内を解析する(太字・斜体・取り消し線・リンク・エスケープ)。式の目印は、そのままスパンになる。

### 決めたこと
- **文章の中の単一の改行は、そのまま改行として残す**(AIの採点レポートが、改行だけで項目を区切るため)。
- 式を含む箇条書きの項目、`$$…$$` を文の途中に書いた場合(前後の文章と式を3つのブロックに分ける)にも対応。
- 項目の間に空行がある箇条書きも、1つの一覧として扱う。
- 太字の中の式は、太字の属性が付く(`**$x=2$**`)。

### 生成の途中(閉じていない記号)
閉じていない `**`、`*`、`` ` ``、リンク、行内の式、表(区切り行がまだない)は、**そのまま文字**として残る。
閉じていない独立した式(`$$…`、`\[…`、`\begin{…}`)は `incompleteMath`、閉じていないコードは `isClosed: false`。
閉じた時点で、正しい構造に変わる。

### 確認
- 解析テスト約35件(見出し・強調・リンク・箇条書き・入れ子・表・コード・独立した式・閉じていない記号)。
- サンプル集: 日本語の文章が欠けない・順序が変わらない、完成した返答に `**` `$` `\frac` が文章に残らない、
  すべての途中状態(2文字ごと)で落ちない。
- 速さ: 約1500文字で約1.3ミリ秒。


## ステップ4(描画部品)の結果

### 部品
- `Views/MathRendering.swift`: 式の正規化・描画可否の検証・行内用の画像生成(キャッシュ付き)・ブロック用 `MathLabel`。
- `Views/RichMessageView.swift`: `RichTextParser` の結果を表示する。見出し・リスト・引用・表・コードブロック・水平線に対応。

### 仕組み
- 段落は SwiftUI の `Text` を連結して作る。行内の数式は `MTMathUILabel` を画面外で描いた画像を `Text(Image)` として埋め込み、`baselineOffset(-descent)` で基準線を合わせる。日本語まじりの文が自然に折り返す。
- ブロックの数式は `MathLabel`(UIViewRepresentable)。提案幅いっぱいを返し、中央寄せ、長い式は折り返す。
- 描けない式(`\boxed`・`\ce`・`\underbrace`、閉じていない式など)は、ステップ2のテキスト変換で代替表示する(例: `H₂O`)。空白のまま表示されることはない。

### 見つかったこと
- 行内画像は上下が反転した → 描画前に縦方向に反転して解消(テストで指数が上半分にあることを確認)。
- SwiftMath が未対応のものを正規化で補う: `\therefore`・`\because`・`\blacksquare`・`\mathscr`・`\hline`/`\cline`・`\displaystyle`・`align`/`align*`(→`aligned`)・`array`(→`matrix`。列の縦線と揃え指定は失われる)。
- 長い返信(約1,500字)のレイアウトは約9ms(キャッシュ後)。

### 確認
- 実機相当のシミュレータで幅700・420の画面を目視確認(日本語+行内数式、分数・根号・総和・極限、表、引用、コード内の `$HOME`、`$100`/`$200` の価格表記、採点レポートの改行保持)。
- `MathRenderingTests`(正規化・描画可否・画像の向き・キャッシュ・日本語・全サンプルのレイアウト・生成途中の各状態・速度)。
