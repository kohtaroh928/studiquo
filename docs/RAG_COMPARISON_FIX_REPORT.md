# 比較・複合質問の対象判定の修正

2026-10-08、残タスク4のうち、実資料で根拠がそろってもpartialとなる3件を修正した。
同じ公開教科書・固定30問で再評価し、jma-21/23/24がpartialからgroundedへ変わった。根拠取得24/24問と、根拠なし6問の出典抑制を維持した。
groundedは返却本文が比較対象をカバーするという判定であり、完全な比較回答や数値の正しさを保証しない。

## 原因と限定した設計

3件とも検索では必要なページとanchorを取得していた。
一方で、質問の「進み方」「代表値」が第二対象の名前に混入したり、修飾語と対象名の連続一致を要求したりしていた。
見出しが「対象（修飾語）」の順の場合も、本文に両方が存在していても一致しなかった。

受け入れ条件は、対象・共有する質問項目を分け、修飾語を保持し、対象別検索を最大3本に抑えること。片側・修飾語・具体的な要求値の根拠が不足するケースを成功扱いにしないこと。実際に返すcontextからcoverageを判断する現行仕様を維持することとした。
独立Plannerで設計を確認し、検索閾値・RRF・Rerankerの重みや詳細根拠ルールは変更不要と判断した。

変更した本番コードは2ファイル。

- `mcp-server/src/rag/query.js`：共有の質問項目に「進み方」「代表値」を追加して対象と分離する。対象別検索にはその項目を残す。両対象それぞれに同じ属性が明記される場合は、各対象の限定語を保持する。検索文への属性の二重追加を避ける。
- `mcp-server/src/rag/ranking.js`：連続一致に加え、「の」で結ばれた複合対象のすべての語句が、同一文・段落内の正規化後160文字以内に存在する場合に認識する。新しい共起判定では別の文・段落の語句を混ぜず、title/metadataを根拠にしない。

canonical queryと質問原文は維持。対象の修飾語を捨てず、別対象への共有条件の自動継承も行わない。
既存retrievalのTop15・Top5・最終contextで同じcoversSubjectを使用するため、判定の適用箇所が一致する。
追加LLM呼び出し、新しいモデル、外部API・レスポンス形式の変更はない。

## 安全性・運用・再現

本文・質問・Embedding・秘密情報のログ追加なし。集計JSONには状態・件数・時間・hashのみを保存する。
schema、migration、binding、secret、プライバシーポリシー上の送信先・保持方針の変更なし。
deploy・本番データ変更なし。production/stagingのRAG_ENABLED=falseを維持。
ロールバックはquery.js/ranking.jsの今回の判定変更を戻す。データ移行や再Embeddingは不要。

## 残る制約

対象抽出は限定した日本語パターンと最大3対象に対応し、任意の自然言語の複合質問を理解するものではない。160文字共起は関係の意味や否定を完全に解析しない。
代表値は現在の数量詳細ルールに含まれず、今回のgrounded改善は数値の意味的正確性を検証したという意味ではない。
次工程は数式・実スキャンPDFのOCR評価と改善。実D1/Vectorize・iPad経路、実教材のGemini回答品質、多分野・私有教材、運用・本番有効化前の確認も残っている。
