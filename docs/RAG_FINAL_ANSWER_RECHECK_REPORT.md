## 修正

検索では `ABC12.3` と `ABC 12.3` を同じ型番として見つけられるようになっていたが、価格などの具体的な事実を照合する後段では別の文字列として扱っていた。このため、正しい価格が取得できても回答可能とは判定されなかった。

`identifiers.js` に比較専用の `identifierText()` を追加し、`answerability.js` の事実照合にも同じ限定的な型番正規化を適用した。原文、Geminiへ渡す取得本文、保存本文、出典は書き換えない。小数、先頭ゼロ、末尾文字、年の違いを同一視せず、別の対象への価格の割当ても受け入れない。

変更ファイルは `mcp-server/src/rag/identifiers.js`、`mcp-server/src/rag/answerability.js`、`mcp-server/src/rag-identifiers.test.js`。新規報告は本書と `RAG_FINAL_ANSWER_RECHECK_RESULTS.json`。この作業で `ai.js` の通常チャットやモデル設定は変更していない。

## 実Geminiでの確認

本番の `handleAI` を通し、検索部分はローカルの合成D1・Vectorize・Workers AIフィクスチャ、最終生成のみ実Geminiを使用した。ユーザー提供PDFは送信していない。生の回答は権限を限定した一時領域のみへ保存し、リポジトリには本文、プロンプト、キーを保存していない。

先に実行した固定12ケースはHTTP 200・生成完了12/12、自動チェック11/12。比較、追質問、部分回答、式・条件不足、命令注入3種類、複数ページというRAGの9ケースでは、確認済みの事実を保持し、不明な値・式・偽出典を作らなかった。返却した構造化出典のページと保存chunkの対応も確認した。これは限られた合成例の確認であり、全体の検索精度や安全性の保証ではない。

残る1件はRAG障害から通常チャットへ切り替わる例。切替自体は成功したが、三角形の内角の和を180度と明示せず、錯角の用語と説明にも誤りがあった。通常AIの回答品質の課題として残す。RAG無効時と検索0件時の別ケースは180度を正しく説明した。情報不足の回答では、何が不足しているのかをより具体的に案内する余地もある。

12ケースの通常モデル `gemini-3.5-flash` は503が6回、429が30回で回答できず、全12件を既存の代替 `gemini-3.5-flash-lite` が回答した。したがって、この12件から通常モデルの品質を評価したとは言えない。API呼出し48回、合成検索を含む応答完了時間の中央値3.821秒、範囲3.477〜8.072秒。成功応答の入力7,771・出力691・合計8,462 tokens。失敗呼出しのusageは未取得で、請求額は未確認。

修正後は追加の型番3ケースを実Geminiで確認し、3/3合格。正しい型番では37円を回答しページ1を引用、小数違いと先頭ゼロ違いでは価格を流用しなかった。今回は通常モデル `gemini-3.5-flash` が3回とも成功した。応答完了3.159〜4.192秒、入力1,880・出力180・thinking 1,637・合計3,697 tokens。先の12件を修正後に再実行したものではない。
