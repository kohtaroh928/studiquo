# staging検証で見つかった問題の修正

2026-10-09。作業先 `.worktrees/rag-wip`。前回の不合格結果を保持して再検証する。本番・既存staging WorkerへのデプロイとRAG有効化は行わない。

## 出典の対象名の取り違え

「ルミナ草」への質問で、「ソラナ草」のページが共通する「草の葉は」等の字句一致だけで採用されていた。`rag/relevance.js` に限定的な対象名照合を追加した。カタカナと漢字で構成される明示的な対象名について、弱い字句一致だけでは本文または局所見出しの名前一致も必要とする。同じ分類語の別名は、高いVector scoreだけでも採用しない。資料タイトルだけを名前の一致根拠にしない。

名前は部分一致ではなく解析した語の完全一致で確認する。「ウルミナ草」を「ルミナ草」と混同しない。比較では各対象の候補を保持する。全体の字句閾値、Embedding、FTS保存形式、hash、ユーザー・scope条件は変更しない。全ての固有名詞を理解する方式ではなく、別表記・同義語・OCRによる名前の崩れを保守的に除外し得る。例えば同じ分類語を持つ別カタカナ表記の同一性は自動判断しない。一般語の高Vectorによる救済は残すが、独立資料での精度調整は必要。

新規の統合回帰テストは、取得contextと出典が正しいページだけになること、比較では両ページを取得することを、Reranker正常・障害・Vector未反映の3条件で確認する。

## Geminiの待ち時間と事実質問

チャットで通常モデルの503を最大3回から2回までにし、429は同じモデルへ繰り返さず既存の代替モデルへ移る。採点・レビューの3回試行は維持。通常モデルと代替が同一の設定でも最大試行は有限で、代替の404が元の混雑エラーを隠さない動作、400の即時終了、破棄レスポンスの解放を保持する。

promptは、事実・定義・値を尋ねる質問には結論を直接答え、解答途中・ヒント要求には考え方を支援することを区別した。特定の数学問題の答えを埋め込んだ修正ではない。RAG無効の通常チャットにも適用する今回の意図的な品質修正で、旧promptとの完全同一性は主張しない。

合成数学問題の実Gemini再測定3回は全て通常モデルで成功。3回とも180度を先に示し、確認した説明で前回の「錯覚」等の誤りはなかった。完了時間は2.692〜3.048秒。前回は全て代替モデルだったため、差を再試行修正だけの効果とみなさない。通常モデルのquota・混雑自体をコードで解消したとは言えず、数学全般の正確さも保証しない。

## Vectorize反映待ちの診断

私有harnessを修正し、upsertのmutationId・登録時刻、処理済みmutation、登録IDの取得、metadataのowner/source/page対応、保存済みVectorを使うaccountKey filter付き検索を確認した。検索側へ長い待機やaccountKeyなし検索は追加していない。検証の待機は最大36回・5秒間隔に拡張し、処理未完了を不正なEmbeddingやHybrid成功と扱わない。

診断では、受付済みupsertより古い処理済みmutationの間は0件、その後処理記録が進むとVectorを取得して自己検索できた。1024次元・有限値・metadataも正しく、今回の0件については非同期反映待ちを確認できた。ただし全ての過去エラーの原因を同一と断定しない。

旧Wrangler 4.130.0で接続エラーも出たため、一時領域の4.149.0で切り分けた。リポジトリの依存は変更していない。新環境では検索範囲・対象出典・差分更新が通過したが、最初の回答検証は私有harnessにRATE_COUNTERがなく500になった。製品コードではなく検証設定の不足であり、製品と同じRateCounter実装をローカルDOへ追加して再実行した。この途中失敗も記録する。
