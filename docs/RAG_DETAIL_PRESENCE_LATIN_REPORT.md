# 答えなし判定：英字の固有語を、資料にあるかの確認に加える

2026-10-22。[金額の単位の修正](RAG_DETAIL_PRESENCE_UNITS_REPORT.md)で残った、英字の固有語（例：ChatGPT）の質問を直した。既存のカタカナ語の確認（[答えなし判定の修正](RAG_DETAIL_PRESENCE_REPORT.md)）を、英字の語にも広げた。対象は `claude/rag-ts`。変更は `mcp-server/src/rag/detail-presence.ts` と `retrieval.ts`。非本文の集計は[RAG_DETAIL_PRESENCE_LATIN_RESULTS.json](RAG_DETAIL_PRESENCE_LATIN_RESULTS.json)。

## 変更

質問中の英字3文字以上の語（大文字小文字は区別しない）が、根拠にも取得した全候補にも、検索範囲の全文にも出てこないとき、その根拠では答えられないと判断する。カタカナ語と同じ条件で動く。

- 英字の部分だけで照合する。型番（「ABC12.3」）は、資料で「ABC 12.3」のように空白を挟んで書かれることがあり、数字を含めて照合すると資料にない語と誤認するため（実装中に既存テストが落ちて判明）。
- 単位の名前（hPa、kt、km など）、「the」「url」などの一般語、2文字以下の語（AI など）は対象外。
- 意味検索と語句検索の1位が同じ抜粋なら、言い換えとして残す条件も、そのまま共通。範囲の確認に失敗したときは、根拠を消さない。
- 数値を質問の対象に結びつける条件（金額・単位の修正）でも、英字の固有語を対象の語として使う。

## 限界

1. **別名での誤判定は、実際に起きる。** 別名の対照4問のうち1問（25%）を落とした。質問に英字の語が入っていて、資料が別の言い方（カタカナ・漢字）で書いているとき、意味検索と語句検索の1位が食い違うと、正解のページがあっても出典が消える。数は4問と少なく率は目安だが、傾向は無視できない。英語の用語を混ぜて質問する利用者には、影響しうる。
2. **それでも、全体では得が大きい。** 今回の測定では、答えなしの防止が+11問（3→14）、答えありの誤判定が1問。ただし、実際の質問での両者の比率は、利用者が英字の語をどれだけ使うかで変わる。
3. 質問は1人（Claude）が作成し、修正の設計を知っている。1冊の教科書だけで測った。この26問も、以後「調整済み」として扱う。
4. SQLの範囲確認は、`lower()`（英字のみ）と部分一致を使う。資料本文に全角の英字があると、範囲に語がないと誤認しうる（取得した候補の本文の確認は、全角を半角に揃えて行うので、通常は候補に入っていれば防げる）。
5. 「出典を抑える」と「資料にないと正しく答える」は別。最終回答は未測定。
