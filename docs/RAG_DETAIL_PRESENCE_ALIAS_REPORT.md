# 英字の別名で正解を落とす問題：対策案の比較と、新しい質問での測定

## 結論

- **案A（質問の残りの語が根拠と強く一致するなら残す）**：別名と、資料にない語で、一致の強さが大きく重なり、分けられない。
- **案B（カタカナ形も確認する）**：英語の綴りから日本語の表記を決める規則がなく、言語モデルが要る。試したところ、小さいモデルは不正確、大きいモデルは遅く、どちらも関連語まで出力して、答えなしを誤って残す。採用できない。
- 補助として調べた「用語そのものの意味ベクトルと根拠の近さ」「語句検索の1位を意味検索の上位Kに入っていれば残す」も、分けられないか、答えなしを誤って残す質問が、救える別名より速く増える。
- 新しい別名の質問（7問）で測ると、**別名の答えあり7問のうち3問を誤って落とす**（前回は4問中1問）。一方、答えなしは10問のうち9問を抑えられる（修正前は3問）。
- 判断（下記）が要る。**今の仕組みの得失は「答えなしの防止が大きく増える代わりに、別名の質問の約3〜4割を落とす」**。

## 案の比較

### 案A：質問の残りの語が根拠と強く一致するなら残す

質問から、資料にない語を除いた残りの語が、取得した根拠にどれだけ含まれるか（語句の一致率）を、答えなしの質問と別名の答えありで比べた（調整済みの全セットのデータ。実行は不要）。

| | 一致率 |
|---|---|
| 別名の答えあり（radar、ridge、AMeDAS、tornado、……） | 0.50〜0.79 |
| 資料にない語の答えなし（Python 0.56、Netflix 0.56、Google 0.50、Windows 0.50、……最大0.67） | 0.00〜0.67 |

重なりが大きく、しきい値で分けられない（0.55前後に置けば別名のradarとridgeを落とし、0.50に置けばPythonやNetflixを残す）。

### 案B：カタカナ形も確認する

英語の綴りは発音と一致しないので（radar→レーダー、ridge→リッジ）、綴りからカタカナを作る規則はない。辞書か翻訳モデルが要る。Workers AIの言語モデルで、英単語を日本語表記に直させて試した。

| モデル | 速さ | 精度 |
|---|---|---|
| llama-3.1-8b | 速い（0.4〜0.9秒） | 不正確。AMeDAS→「天気観測台」、Python→「ピタゴラス」。TensorFlow→「機械学習」のように、関連語も出す |
| llama-3.3-70b | 遅い（Python 6.7秒、ChatGPT 12.8秒。検索全体の上限は10秒） | ほぼ正確（AMeDAS→アメダス、radar→レーダー）。ただし関連語（「プログラミング」「機械学習」など）も出す |

関連語まで出力されるため、資料に「機械学習」があれば、TensorFlowの質問を誤って残してしまう。遅延・費用・出力のばらつきも加わり、Workers AIの呼び出し数の契約（埋め込み3・リランク1）も変わる。実装しても、別名は救えるが答えなしを誤って残すため、得にならない。

### 補助として調べたもの

- **用語そのものの意味ベクトルと、取得した根拠のページの近さ**：別名は0.30（AMeDAS）〜0.50（radar）、資料にない語は0.28〜0.43（TensorFlow 0.43、Google 0.43）。重なり、分けられない。
- **語句検索の1位が、意味検索の上位Kにも入っていれば残す**（今は「1位どうしが同じ」だけ）。調整済みの全セット（別名の答えあり11、資料にない語の答えなし39）で試算した。

| 条件 | 別名を残せた | 答えなしを誤って残した |
|---|---:|---:|
| 1位どうしが同じ（現行） | 7/11 | 2/39 |
| 意味検索の上位3 | 7/11 | 4/39 |
| 同上 上位5 | 7/11 | 6/39 |
| 同上 上位10 | 8/11 | 10/39 |

緩めても別名はほとんど増えず、答えなしの誤りだけが増える。radarの質問では、語句検索の1位（正解のページ）が、意味検索の上位10件にも入っていない。現行の条件が、ほぼ最適。

## 限界

1. 17問と少なく、率は目安。別名の質問は、私が英字の語を足して作ったもので、実際の利用者の書き方とは違うかもしれない。別名の割合は、利用者が英語の用語をどれだけ混ぜるかで変わる。
2. 「出典を抑える」と「資料にないと正しく答える」は別。最終回答は未測定。落とした質問は `insufficient` か `no_match` になり、出典なしで答えが生成される（資料にないとは断定しない指示つき）。
3. v4とv5の質問は、以後「調整済み」として扱う。

## 判断してほしいこと

| 選択肢 | 得 | 失 |
|---|---|---|
| 現行を維持する（推奨） | 答えなしの防止が大きく増えた（上記）。実装は単純で、追加費用はない | 別名の質問の3〜4割を落とす。落とした質問は、出典なしで答えが返る（利用者は言い換えて聞き直せる） |
| 小文字だけの英単語を検査しない | 別名の誤判定がほぼなくなる | 小文字で書いた答えなしの質問が、防げなくなる |
| 英字の確認を外す | 別名の誤判定がなくなる | 答えなしの防止が、前の水準に戻る |
| 意味の判定（大きいモデルで、質問と根拠が対応するかを判定する） | 別名も答えなしも、同時に改善する可能性 | 遅延・費用・出力のばらつき、AI呼び出しの契約の変更。設計判断が別に要る |

どれを選ぶかは、利用者の質問の傾向（英字の語が資料にない語の質問か、別名か）で変わる。アプリのログで、`insufficient`・`no_match` の件数と、利用者が聞き直した割合を見られるようにするのが、判断の根拠として有効。
