## 答えあり74問

- 判定による停止0、降格0。確率は最小0.54、中央値0.91、最大0.95。答えなし（判定が呼ばれた18問）は最小0.07、中央値0.14、最大0.65。**分布はよく分かれているが、重なりが0.54〜0.65にある。**
- 判定とは無関係に、比較・2主題の答えあり18問のうち10問は判定なしでも`partial`（既存の比較の判定による）。残る8問はgrounded。答えあり74問のうち正解の位置を引けなかったのは2問（判定の有無で同じ）。
- 確率が低めだった答えあり：0.60と0.54（後者は2主題でpartialは既存の結果）。0.5のpartialしきい値までの余裕は小さい。

## 気づいたこと・限界

1. **確率は実行ごとに揺れる。** 単位の質問1問は、shadowで0.17（停止の範囲）だったのに、onの実行ではpartialだった（0.25以上0.5未満の確率が出た）。境界付近の質問の結果は固定ではない。0.15〜0.35の質問が6問あった。
2. 母数が小さい：効果の分母は15問、種類別は1〜6問。80%という数字の信頼区間は広い（おおよそ55〜93%）。
3. 1つの資料、私が作った質問。答えなしの語の不在は全文検索で確認したが、言い換えで答えがある可能性は完全には排除していない。
4. 検索はローカル代替（FTS5・厳密なコサイン）。本番のD1／Vectorizeとは細部が違いうる。
5. 検索段階の状態だけを測った。最終回答の質と、出典表示の見え方は測っていない（[最終回答の測定](RAG_FINAL_ANSWER_PROBE_REPORT.md)参照）。
6. タイムアウト2回はいずれも2.0秒の上限に近い実行で、答えありだった。fail-openなので誤停止にはならない。遅延は、判定が呼ばれた問の経過時間が約2〜3秒だった（判定なしとの厳密な比較はしていない）。

## 推奨

1. しきい値（0.25／0.5）は変更しない。事前基準は満たした。
2. `RAG_JUDGE`の本番有効化は、まずshadowで本番の確率分布（RB-21のログ）を集め、答えあり側の下側の裾（0.5付近）と答えなし側の上側の裾を確認してから`on`に進む。
3. 境界付近の揺れを減らしたい場合は、判定を複数回にするのでなく、`stopBelow`を0.2にする案があるが、**この質問で調整すると独立の検証でなくなる**ので、新しい質問を別に作ってから行う。
