# 利用者指定PDFの端末内評価（2026-10-09）

## 対象と結論

利用者が指定したPDFは114ページ、5,768,451 bytes。全ページに文字レイヤーがあり、PDFKitで代表ページを目視確認したところデジタルスライド形式だった。実教材・100ページ超PDFの評価として扱う。紙を撮影した際の傾き、影、折れ、手書き、文字レイヤーがない実スキャンの品質をこの資料から推定しない。

今回の全114ページの処理はMac上で実施した。実iPadはMacから接続不可のため未実施。実iPad・実紙スキャンという依頼全体が完了したとは扱わない。

アプリと同じRAGDocumentTextExtractionServiceの認識・本文統合を使用し、PDFKitのサムネイルを認識した。累計時間は各ページのOCR＋統合部分の計測値で、PDF描画、アプリ操作、通信、Embedding、検索、回答生成を含まない。Mac値をiPadの速度とみなさない。

確認フラグは数式候補、OCR補足の棄却等で立つ保守的な判定で、99ページの認識が失敗したという意味ではない。補足として棄却された候補は合計580行。元本文は保持されている。警告が多い点の改善は別タスク。

短いスライドなので全ページ1 chunk、最大推定265 tokens。ページ末尾の短いchunkとして扱い、300 tokensに達するために他ページの本文を足していない。この資料では複数chunkのoverlapを評価できない。

## 見出し・検索の限定確認

物理ページ1、20、40、60、80、100の見出しを、元文字レイヤーとOCR結果で照合し6/6一致した（空白・NFKCの比較正規化）。これは独立に全文を書き起こした文字正答率、CER/WER、数式構造の正答率ではない。

同じ6見出しを質問語として、製品のchunking/searchTokens/importantText/scopeFilterと、製品のBM25検索SQLをローカルSQLite FTS5上で実行した。library/notebook/folder/current pageの4 scopeで各対象ページがTop5に入り、24 scope確認すべて一致した。独立した24質問ではなく6質問×4 scopeである。資料は1件だけなので、別資料・別folder・他ユーザーの混入防止を新たに検証した結果ではない。

Vectorize、Workers AI、RRF、Reranker、Geminiは実行していない。この確認からHybrid RAG全体の精度や最終回答の正しさを推定しない。

## 実iPad評価の準備

既存studiquoと異なるBundle IDの評価アプリに、指定PDFをprivate resourceとして追加した。全114ページを逐次認識し、元本文保持、認識エラー、ページ単位時間、認識本文、処理後resident memoryをprivate XCTest添付へ記録する評価を準備した。100回同じ画像を処理する既存負荷テストとは分離している。

iOS test buildは成功（署名なしのビルド検証）。実端末へのインストール・実行は接続待ちで、実行0件。メモリ、速度、オフライン、中断、出典タップの実機結果はまだない。処理後resident memoryの最大値を、瞬間的なpeak memoryと誤って報告しない。

再開用ツールは `/private/tmp/studiquo-rag-math-v1/device-harness/resume.py`。端末をUSBまたはネットワークで接続し、解除後に実行する。既存studiquoを置換しない。個人資料を同梱した評価アプリは本番配布しない。
